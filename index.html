背景

为什么需要 ds.hn

ds.hn 的名字来自 DeepSeek Harness Network —— 为每一个本地运行的 dsh（DeepSeek Harness）提供公网入口。 dsh 是运行在你自己机器上的本地 Web UI；当你需要在手机上继续会话、 在外部网络查看任务进度，或将界面共享给同事时，就必须把 127.0.0.1 暴露到公网 —— 而这存在两个问题：

其一，通用隧道无法工作。 dsh 的 /api 设有浏览器信任栅栏：请求的 Host 若非本机回环地址，一律返回 403。ngrok、frp 等通用隧道原样转发公网 Host —— 页面可以加载，接口调用全部失败。

其二，直接暴露等于交出一个远程 Shell。 dsh 内置 bash 与文件系统工具， 一个没有访问控制的公网 dsh，就是一个对任何人开放的远程终端。

dshn 以插件形态同时解决这两个问题：它在 dsh 内部将每个转发请求的 Host/Origin 重写为本机回环地址，信任栅栏照常放行；同时所有公网访问必须先通过中继的登录门禁 —— 安全由门禁承担，而非依赖信任栅栏。

凭据即注册

没有账号体系。首个以空闲子域连接的插件即完成认领，密码哈希落盘；此后每次连接与每次浏览器登录都必须匹配同一密码 —— 从机制上杜绝抢注。

出站连接，无需公网

插件从你的机器主动向中继发起 WSS 连接，家庭宽带、NAT 之后、无公网 IP 均可使用，无需配置端口映射。

中继仅转发字节

开启端到端加密后，中继与 Cloudflare 均只经手密文；解密仅发生在你的浏览器与你的机器两端。

注册与引导

四步上线

无需访问任何注册页面 —— 注册流程完全在 dsh 界面内完成。

安装插件

从 npm 安装 @dshn/agent（完全自包含；离线 tarball 与源码安装方式见 GitHub）：

dsh plugin --profile web add @dshn/agent

启动并打开本地 dsh

照常启动，在浏览器打开本地地址：

dsh --profile web
# 浏览器访问 http://127.0.0.1:3080

设置子域与密码，点击「连接」

首次在本机打开时会自动弹出注册面板（此后位于 设置 → 公网转发）： 填写子域前缀（不少于 4 字符）与访问密码（不少于 8 位，带强度提示），建议同时在 🔒 字段设置 端到端加密密码，使中继自始至终仅经手密文。 点击「连接」后，面板即显示你的公网地址。

随处访问

在手机或任何设备上打开 https://你的子域.ds.hn， 输入同一访问密码登录。若已启用端到端加密，页面会再显示一道解锁框，输入 E2E 密码即可。

⚠️ 三项须知
  • 密码即凭据，云端无法找回。断开连接前请先在面板中复制并妥善保存 —— 子域认领后仅认此密码。
  • 一个子域仅运行一个插件实例。两台设备使用同一组凭据会相互抢占连接，导致隧道反复中断。
  • 端到端加密仅在远程访问时生效。本机 127.0.0.1 访问不会出现解锁框 —— 这是设计行为，并非未生效。
安全

明确的边界

公网可达的 dsh 本质上是一个远程 Shell。dshn 对风险与能力边界均如实说明：

✅

登录门禁不可关闭。任何请求在通过密码验证、换取签名 Cookie 之前，不会被代理至你的机器。

✅

暴力破解防护。15 分钟内错误 8 次即锁定 10 分钟，按「子域 + 访客 IP」计数，攻击者仅会锁定自身。

✅

管理接口不出本机。查看密码、修改配置、断开隧道的接口在公网侧一律返回 404，已登录访客亦无法访问。

✅

端到端加密防御被动读取。开启后 API 内容以 AES-256-GCM 封装，中继运营方与 Cloudflare 仅见密文；即使服务器被入侵，历史流量亦不可读。

⚠️

无法防御主动作恶的中继。页面 JS 仍由中继下发，主动篡改页面的中继理论上可绕过 E2E。彻底解决需 TLS 直通或原生客户端 —— 我们不做超出实际能力的承诺。

💡

高吞吐可走直连。Cloudflare 在持续高吞吐下可能重置隧道连接；插件支持直连源站（自签证书钉扎），绕开边缘限制。

FAQ

常见问题

ds.hn 这个名字是什么意思？
DeepSeek Harness Network —— 由一个个本地运行的 dsh（DeepSeek Harness）组成的网络，每个实例以 你的名字.ds.hn 的形式接入公网。
为什么不用 ngrok / frp / Cloudflare Tunnel？
通用隧道原样转发公网 Host，会被 dsh 的 /api 浏览器信任栅栏拒绝（403）—— 页面可以加载，接口全部报错；且它们默认没有登录门禁，等于将一个远程 Shell 无防护地暴露于公网。 dshn 作为 dsh 插件在内部完成 Host/Origin 重写，同时强制登录，两个问题一并解决。
子域是怎么分配的？会被抢注吗？
先到先得：首个以空闲子域连接的插件完成认领，同时设定该子域的密码（服务端仅存 scrypt 哈希）。 此后以该子域连接必须匹配同一密码 —— 未持有密码者无法顶替现有连接。
忘记密码了怎么办？
云端无法找回（服务端仅存哈希）。只要插件仍在本机运行，即可随时在面板中查看并复制当前密码； 请在断开连接前妥善保存。凭据同时持久化于本地 dsh 配置。
流量经过哪些环节？有何限制？
浏览器 → Cloudflare 边缘 → 自托管中继 → 你机器上的插件 → 本地 dsh。边缘带宽不计量。 已知限制：Cloudflare 免费计划单次请求体上限 100MB；持续高吞吐场景建议启用直连源站模式。
我的机器需要公网 IP 或端口映射吗？
不需要。插件从你的机器主动向中继发起 WSS 连接，家庭宽带、NAT、企业内网均可使用。
端到端加密具体覆盖哪些内容？
/api 请求响应内容与下行事件消息（PBKDF2-SHA256 210,000 轮派生密钥 → AES-256-GCM）。 应用外壳与静态资源保持明文以完成浏览器引导。E2E 密码不会发送至服务器，访客在浏览器中输入后本地解密。
