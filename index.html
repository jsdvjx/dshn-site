背景

为什么需要 ds.hn

ds.hn 的名字来自 DeepSeek Harness Network —— 为每一个本地运行的 dsh（DeepSeek Harness）提供一个公网入口。 dsh 是跑在你自己机器上的本地 Web UI。它很好用 —— 直到你想在手机上继续会话、 出门后接着看任务进度，或者把界面递给同事看一眼。这时你需要把 127.0.0.1 暴露到公网，而这有两个坑：

其一，普通隧道根本打不通。 dsh 的 /api 有一道浏览器信任栅栏：请求的 Host 不是本机回环就直接 403。ngrok、frp 这类通用隧道原样转发公网 Host，页面能开、接口全挂。

其二，裸暴露等于交出一个远程 Shell。 dsh 自带 bash 和文件系统工具， 一个没有门禁的公网 dsh，就是任何人都能用的你机器上的终端。

dshn 插件用「插件」这个身份同时解决两件事：它在 dsh 内部把每个转发请求的 Host/Origin 回写为本机回环，信任栅栏照常放行；同时所有公网访问都必须先过中继的登录门禁 —— 安全由门禁负责，而不是靠栅栏硬扛。

能力

开箱即用的一整套

⚡️

一分钟注册，零审批

子域前缀 + 密码，两样就是全部凭据。没有 token、没有环境变量、没有等待审核 —— 先到先得，第一个认领子域的人设定它的密码（服务端只存 scrypt 哈希）。

登录门禁

公网访客必须输入同一密码，换取按域名限定、HMAC 签名的 Cookie 后才会被代理。15 分钟内错 8 次即锁定 10 分钟，且按访客 IP 计，攻击者锁不住你自己。

🔐

端到端加密

再设一个独立的 E2E 密码（永不发给服务器），API 内容以 AES-256-GCM 封装 —— 中继运营方与 Cloudflare 都只见密文。了解更多 →

🌍

Cloudflare 边缘

所有 *.ds.hn 流量走 Cloudflare 全球边缘：免费 DDoS 防护、WAF、TLS、Anycast 加速，源站 IP 对外不可见。

🧩

原生长在 dsh 里

配置就在 dsh 自己的设置页「公网转发」一节；侧栏常驻入口实时显示隧道延迟（Cloudflare 链路实测 ~18ms）。不是外挂脚本，是一等公民插件。

🔁

断线自愈

双端每 25 秒心跳保活，掉线自动重连；凭据持久化在本地配置中，dsh 重启后隧道自动恢复，无需重新设置。

📡

完整协议转发

HTTP 与 dsh 的事件 WebSocket 全量回放，一条多路复用 WSS 承载全部流量。真实页面 40 个资源包加载 0 失败。

🛡

管理面只在本机

插件的管理接口在隧道里一律 404，改配置、看密码只能在你自己机器上进行。子域至少 4 字符、密码至少 8 位，断开连接需二次确认。

端到端加密

密文穿过中继，明文只在两端

登录门禁挡住陌生人；端到端加密更进一步 —— 你的会话内容，连中继运营方、连 Cloudflare 都读不到。再设一个独立的 🔒 E2E 密码，它永远不会发给任何服务器： 你的浏览器用它加密，你的机器用它解密，中间每一跳经手的都只是密文。

密钥派生

E2E 密码经 PBKDF2-SHA256（210,000 轮 + 随机盐）派生出 AES-256-GCM 密钥。盐是公开的；密码与密钥永不出你的设备。

🙈

服务器零内容

中继与 Cloudflare 经手的 API 内容与事件流全部是密文 —— 即使服务器被入侵，攻击者翻查到的历史流量也不可读。

📦

加密范围

/api 请求与响应、下行事件流全部封装；应用外壳与静态资源保持明文，浏览器才能完成引导。

🎚

一次设置，按需开启

注册面板的 🔒 一栏填一次即可；远程访客首次打开会看到解锁框，输入同一 E2E 密码即通。本机 127.0.0.1 访问不受影响。

边界诚实说：它防的是「被动 / 好奇」的中继与服务器数据泄露；页面 JS 仍由中继下发，所以它不防主动篡改页面的中继 —— 详见安全边界。

原理

它是怎么工作的

凭据即注册

没有账号系统。第一个带着空闲子域连上来的插件完成「认领」，密码哈希落盘；之后的每次连接、每次浏览器登录都要对上同一密码 —— 天然防抢注。

出站连接，无需公网

插件从你机器主动拨出 WSS 到中继，家庭宽带、NAT 之后、无公网 IP 都能用，不用配路由器端口映射。

中继只搬字节

开启端到端加密后，中继与 Cloudflare 都只见密文；解密只发生在你的浏览器和你的机器两端。

注册与引导

四步上线

全程不需要打开任何注册网页 —— 注册这件事，就发生在 dsh 自己的界面里。

安装插件

把 dshn-agent 插件加入你的 dsh profile：

dsh plugin --profile web add /path/to/dshn/dist/dshn-agent

启动并打开本地 dsh

照常启动，然后在浏览器打开本地地址：

dsh --profile web
# 浏览器访问 http://127.0.0.1:3080

起名、设密码，点「连接」

首次打开会自动弹出注册面板（之后也能在 设置 → 公网转发 找到）： 填一个子域前缀（≥4 字符）和一个访问密码（≥8 位，带强度提示），并建议顺手在 🔒 一栏设置 端到端加密密码 —— 让中继从第一天起就只见密文。 点「连接」，面板立即显示你的公网地址。

随处访问

在手机或任何设备上打开 https://你的子域.ds.hn， 输入同一个访问密码登录。如果设了端到端加密，页面会再弹一道解锁框，输入 E2E 密码即可。

⚠️ 三件必须知道的事
  • 密码就是凭据，云端无法找回。断开前先在面板里「复制密码」保存好 —— 子域认领后只认这个密码。
  • 一个子域只跑一个插件实例。两台机器用同一组凭据会互相顶掉，隧道反复闪断。
  • 端到端加密只在远程访问时生效。本机 127.0.0.1 打开不会出现解锁框，这是设计如此，不是没生效。
安全

边界说清楚

公网可达的 dsh 本质上是一个远程 Shell。dshn 把风险摆在明面上，也把边界说在明面上：

✅

登录门禁不可关闭。任何请求在验证密码换取签名 Cookie 之前，不会被代理到你的机器。

✅

暴力破解有锁。15 分钟内错 8 次锁 10 分钟，按「子域 + 访客 IP」计数，攻击者只能锁住他自己。

✅

管理接口出不了本机。查看密码、改配置、断开隧道的接口在公网侧一律 404，即使已登录的访客也碰不到。

✅

端到端加密防「好奇的中继」。开启后 API 内容以 AES-256-GCM 封装，中继运营方与 Cloudflare 只见密文，即使服务器被入侵，历史流量也不可读。

⚠️

它不防「主动作恶的中继」。页面本身（JS）仍由中继下发，一个主动篡改页面的中继理论上可以绕过 E2E。这需要 TLS 直通或原生客户端才能根治 —— 我们不假装已经做到。

💡

大流量可走直连。Cloudflare 在持续高吞吐下可能重置隧道连接；插件支持配置直连源站（自签证书钉扎），绕开边缘限制。

FAQ

常见问题

ds.hn 这个名字是什么意思？
DeepSeek Harness Network —— 由一个个本地运行的 dsh（DeepSeek Harness）组成的网络，每个实例以 你的名字.ds.hn 的形式接入公网。
为什么不用 ngrok / frp / Cloudflare Tunnel？
通用隧道原样转发公网 Host，会被 dsh 的 /api 浏览器信任栅栏 403 —— 页面打得开，接口全报错。 而且它们默认没有登录门禁，等于把一个远程 Shell 裸奔在公网。dshn 作为 dsh 插件在内部完成 Host/Origin 回写，同时强制登录，两个问题一起解决。
子域是怎么分配的？会被人抢注吗？
先到先得：第一个带着空闲子域连接的插件完成认领，同时设定这个子域的密码（服务端只存 scrypt 哈希）。 之后任何人想用这个子域连接，都必须对上同一密码 —— 抢注者拿不到你的密码，也就顶不掉你。
忘记密码了怎么办？
云端无法找回（服务端只有哈希）。只要你的插件还在本机运行，随时可以在面板里查看并复制当前密码； 所以请在断开连接之前先把密码复制保存好。凭据也会持久化在本地 dsh 配置中。
流量经过哪些地方？限速吗？
浏览器 → Cloudflare 边缘 → 自托管中继 → 你机器上的插件 → 本地 dsh。边缘带宽不计量； 已知限制：Cloudflare 免费计划单次请求体上限 100MB（超大文件上传会被截），持续高吞吐场景建议启用直连源站模式。
我的机器需要公网 IP 或端口映射吗？
不需要。插件从你的机器主动向中继拨出一条 WSS 连接，家庭宽带、NAT、公司内网都能用。
端到端加密具体加密了什么？
/api 请求响应内容与下行事件消息（PBKDF2-SHA256 21 万轮派生密钥 → AES-256-GCM）。 应用外壳与静态资源保持明文以便浏览器引导。E2E 密码永远不会发给服务器，访客在浏览器里输入后本地解密。
