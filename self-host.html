自托管

在你自己的域名上，
运行你自己的网络

ds.hn 并非唯一入口。中继以 @dshn/relay（npm）与 Docker 镜像发布，可部署在你自己的服务器与域名之上；dsh 侧安装同一个 @dshn/agent 插件，通过 DSHN_RELAY_HOST 指向你的中继即可 —— 认领、门禁、端到端加密等全部能力保持一致。 完整文档见 SELF-HOSTING.md。

⚠️ 安全前提 公网可达的 dsh 是一个远程 Shell（dsh 内置 bash 与文件系统工具）。中继的登录门禁是互联网与该 Shell 之间的唯一屏障 —— 请为每条隧道设置高强度密码，并优先启用端到端加密。不要向你无法控制访问策略的中继暴露 dsh。
准备条件

你需要什么

🖥

一台服务器

具备公网 IP。中继是单个 Node 进程，内存占用约 30 MB，对配置几乎没有要求。

🌐

一个域名（apex）

可添加 DNS 记录的域名，例如 tunnel.example.com。需要两条 A 记录指向中继 IP：apex 本身与 *.apex 泛解析。

🔐

一份 *.apex 的 TLS

三种方案见下文。注意通配符证书仅覆盖一级子域，隧道名须保持单层（如 alice.tunnel.example.com）—— 中继亦强制此规则。

A  tunnel.example.com    → <中继 IP>   # apex：agent 拨号目标，兼登录主机
A  *.tunnel.example.com  → <中继 IP>   # 泛解析：每条隧道都在这里
部署

三步完成

运行中继

方式 A —— npm（Node ≥ 20）。唯一必填的只有 apex。登录密钥会在首次运行时自动生成并持久化（不用 openssl rand），claims 文件与密钥都放在 --data-dir 里：

npx @dshn/relay --apex tunnel.example.com --data-dir /var/lib/dshn

--help 列出全部参数；每个参数也有对应环境变量（如 DSHN_APEX），二选一即可。

长期运行建议注册为 systemd 服务（DynamicUser + StateDirectory，随系统自启）：

# /etc/systemd/system/dshn-relay.service
[Unit]
Description=dshn relay
After=network.target

[Service]
ExecStart=/usr/bin/npx --yes @dshn/relay --apex tunnel.example.com --data-dir /var/lib/dshn
Restart=always
DynamicUser=yes
StateDirectory=dshn

[Install]
WantedBy=multi-user.target
sudo systemctl enable --now dshn-relay

方式 B —— Docker

docker run -d --name dshn-relay --restart unless-stopped \
  -p 8787:8787 \
  -e DSHN_APEX=tunnel.example.com \
  -v dshn-data:/data \
  ghcr.io/jsdvjx/dshn-relay:latest

镜像默认把 --data-dir 设为 /data，自动生成的密钥与 claims 都持久化在 dshn-data 卷上——除了 apex 无需再设任何东西。仓库亦提供 docker-compose.yml（DSHN_APEX=tunnel.example.com docker compose up -d）。

配置 TLS（三选一）

中继承载 WebSocket，全程需要 wss://（TLS）。

Cloudflare 之前置（最简单，且隐藏源站）。 将 *.apex 与 apex 以代理模式（橙色云）指向中继；中继本身服务明文 HTTP，由 Cloudflare 终结 TLS，SSL 模式设为 Full。Cloudflare 约 100 秒关闭空闲 WebSocket，中继每 25 秒心跳，隧道不受影响。请将源站加固为仅接受 Cloudflare IP 段并启用 Authenticated Origin Pulls —— 源站信任 cf-connecting-ip。

独立部署 + 正式证书（不经 Cloudflare）。 通过 Let's Encrypt DNS-01（certbot --preferred-challenges dns）签发 *.apex 通配符证书，中继直接服务 443： 

npx @dshn/relay --apex tunnel.example.com --data-dir /var/lib/dshn --port 443 \
  --tls-cert /etc/letsencrypt/live/tunnel.example.com/fullchain.pem \
  --tls-key  /etc/letsencrypt/live/tunnel.example.com/privkey.pem

绑定 443 需要 root 或 CAP_NET_BIND_SERVICE；agent 走公共 CA，无需额外配置。

自签证书（私有 / 内网）。 以 SAN 覆盖 *.apex 的自签证书服务 HTTPS，agent 侧用 DSHN_ORIGIN_CA 钉扎该证书（见下一步）。

将 dsh agent 指向你的中继

照常安装插件后,最简单的方式是在 设置 → 公网转发 里选 自托管、填入中继地址即可(无需环境变量)。或在启动 dsh 时用环境变量指定:

dsh plugin --profile web add @dshn/agent
DSHN_RELAY_HOST=wss://tunnel.example.com dsh --profile web

DSHN_RELAY_HOST 填能到达中继的主机：apex 可用，保留字子域 relay.<apex>（用户不可认领）亦可；非 443 端口需显式写出（如 wss://tunnel.example.com:8787）。自签证书场景另设 DSHN_ORIGIN_CA 指向中继证书 PEM，agent 将其钉扎为唯一 CA。

随后打开 dsh → 设置 → 公网转发，填写子域前缀与密码并连接。 首个认领空闲子域的 agent 设定其密码（信任首次使用），以 scrypt 哈希存储在你的中继上。

参考

配置参考

每个配置项都是命令行参数（--flag value）或对应的环境变量，参数优先。npx @dshn/relay --help 查看实时列表。

参数环境变量默认值用途
--apexDSHN_APEXds.hn泛解析所挂靠的 apex 域名
--data-dirDSHN_DATA_DIR./dshn-data存放 claims.json 与自动生成的 cookie-secret
--portDSHN_RELAY_PORT8787监听端口
--secretDSHN_COOKIE_SECRET自动生成Cookie HMAC 密钥；想固定时才设置
--claimsDSHN_CLAIMS<data-dir>/claims.json认领表：子域 → scrypt 哈希
--tls-cert / --tls-keyDSHN_TLS_CERT / DSHN_TLS_KEY—PEM 路径，直接服务 HTTPS（省略则明文 HTTP，置于 TLS 终结代理之后）
--siteDSHN_SITE—裸 apex 的落地页 index.html（同目录扁平 .html/.css 一并服务）
—DSHN_DEBUG—设置后将连接生命周期日志输出至 stderr
🔑

密钥零配置。无需设置 Cookie 密钥：首次运行自动生成强随机密钥并存入 <data-dir>/cookie-secret（权限 600），重启复用、会话不失效。

💾

备份 claims.json。它是子域归属的唯一记录，丢失后所有名称可被重新认领。文件以原子方式写入，权限 600。

1️⃣
